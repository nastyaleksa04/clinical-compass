# Врачебный RAG-помощник через OpenRouter

Версия прототипа: 0.15.1.

## Настройка

~~~bash
cd /mnt/d/datacon_2026/clinical-compass
cp .env.example .env
nano .env
~~~

В файле .env укажите:

~~~text
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=qwen/qwen3.8-flash
~~~

Затем перезапустите сервер:

~~~bash
bash run-local.sh
~~~

Файл .env исключён из Git. Ключ остаётся на сервере и не передаётся браузеру.

Для PowerShell можно задать переменные только на текущую сессию:

~~~powershell
$env:OPENROUTER_API_KEY="ваш_ключ"
$env:OPENROUTER_MODEL="qwen/qwen3.8-flash"
python scripts/web_service.py --port 8000
~~~

## Как работает запрос

1. POST /api/rag/answer принимает вопрос врача.
2. Локальный retrieval выбирает до шести фрагментов KB v2.2.
3. В OpenRouter отправляются вопрос и найденные фрагменты.
4. Модель получает требование отвечать только по контексту и ставить ссылки [1], [2].
5. API возвращает ответ, модель, техническую статистику и отдельный список цитат.

GET /api/rag/status сообщает браузеру только статус подключения, модель и версию индекса. API-ключ в ответ не попадает.

На этом этапе нельзя вводить ФИО, контакты и другие данные пациента: интеграция предназначена для общих клинических вопросов по базе. Контекст карточки пациента в OpenRouter не отправляется.

Проверка ссылок подтверждает, что номера вида [1] существуют среди выданных фрагментов. Она не проверяет медицинскую истинность каждого предложения модели. Решение и итоговая проверка остаются за врачом.

При пустом финальном ответе провайдера клиент один раз повторяет запрос без reasoning. Обычный запрос Qwen выполняется с низким объёмом reasoning и увеличенным лимитом финального ответа.
