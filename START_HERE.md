# Клинический компас — инструкция по запуску

В архиве находится локальный прототип связанных кабинетов пациента и врача. Сервер работает на FastAPI, данные сохраняются в SQLite, интерфейс открывается в обычном браузере.

## 1. Что потребуется

- Ubuntu 22.04 или более новая версия;
- Python 3.10 или новее;
- интернет при первом запуске для установки Python-зависимостей;
- свободный порт 8000.

Проверка Python:

~~~bash
python3 --version
~~~

Если Python или модуль venv не установлен:

~~~bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip unzip
~~~

## 2. Распаковка

Перейдите в папку, где лежит ZIP, и выполните:

~~~bash
unzip clinical-compass-v0.12.0-ubuntu.zip
cd clinical-compass
~~~

Если архив находится на диске D в WSL:

~~~bash
cd /mnt/d
unzip clinical-compass-v0.12.0-ubuntu.zip
cd clinical-compass
~~~

## 3. Запуск

~~~bash
chmod +x run-local.sh
bash run-local.sh
~~~

При первом запуске скрипт:

1. создаст папку .venv внутри проекта;
2. установит зависимости из requirements.txt;
3. создаст или обновит локальную SQLite-базу;
4. запустит сайт.

Откройте в браузере:

- сайт: http://localhost:8000
- проверка API: http://localhost:8000/api/health
- интерактивная документация API: http://localhost:8000/docs

Остановка сервера: Ctrl+C.

## 4. Повторный запуск

Повторная установка пакетов не требуется:

~~~bash
cd clinical-compass
bash run-local.sh
~~~

## 5. Другой порт

Если порт 8000 занят:

~~~bash
PORT=3000 bash run-local.sh
~~~

Тогда сайт будет доступен по адресу http://localhost:3000.

## 6. Открытие с телефона в одной Wi-Fi-сети

Запустите сервер с доступом из локальной сети:

~~~bash
bash run-local.sh --host 0.0.0.0
~~~

Узнайте IP-адрес ноутбука:

~~~bash
hostname -I
~~~

На телефоне откройте адрес с IP ноутбука, например http://192.168.1.25:8000.

Если страница не открывается, разрешите порт в локальном firewall. Не публикуйте этот демонстрационный сервер в интернете.

## 7. Вход и смена кабинета

После заставки Нейрона откроется экран входа. Демо-учётные записи:

- врач — `doctor` / `doctor2026`;
- пациент — `patient` / `patient2026`.

Кнопки «Врач» и «Пациент» в блоке «Демо-доступ» входят одним нажатием. Чтобы сменить кабинет, нажмите «Выйти» в правой части верхней панели и войдите под другой учётной записью.

Все пациенты и медицинские сведения в поставке синтетические.

## 8. Данные и резервная копия

Локальная база:

~~~text
data/clinical_compass.db
~~~

Чтобы сохранить текущее состояние, остановите сервер и скопируйте файл:

~~~bash
cp data/clinical_compass.db data/clinical_compass.backup.db
~~~

Чтобы вернуть исходные демонстрационные данные:

~~~bash
rm -f data/clinical_compass.db
bash run-local.sh
~~~

При следующем запуске база будет создана заново и заполнена синтетическими сценариями.

## 9. Автоматические тесты

После первого запуска:

~~~bash
source .venv/bin/activate
python -m unittest discover -s tests -v
deactivate
~~~

Ожидаемый результат поставки: 81 тест, статус OK.

## 10. Ручной запуск сервера

~~~bash
source .venv/bin/activate
python scripts/web_service.py --port 8000
~~~

Режим автоматического перезапуска после изменения кода:

~~~bash
python scripts/web_service.py --port 8000 --reload
~~~

## 11. Частые проблемы

### No module named venv

~~~bash
sudo apt install -y python3-venv
~~~

### Порт уже занят

~~~bash
PORT=3000 bash run-local.sh
~~~

### Зависимости не устанавливаются

Проверьте интернет, затем удалите незавершённое окружение и повторите запуск:

~~~bash
rm -rf .venv
bash run-local.sh
~~~

### Браузер показывает старую версию интерфейса

Выполните жёсткое обновление страницы: Ctrl+Shift+R.

## 12. Основные папки

~~~text
app/          FastAPI, клинические правила и работа с SQLite
config/       шкалы, препараты, алертинг и демонстрационные сценарии
dist/         HTML, CSS, JavaScript и изображения
scripts/      запуск сервера и служебные скрипты
tests/        автоматические тесты
data/         локальная SQLite-база
~~~

Прототип не предназначен для работы с реальными медицинскими данными и не выполняет клинические действия без подтверждения врача.


## 13. Подключение OpenRouter

~~~bash
cp .env.example .env
nano .env
~~~

Добавьте OPENROUTER_API_KEY, сохраните файл и перезапустите bash run-local.sh. В кабинете врача откройте «Знания»: статус помощника должен измениться на OpenRouter и выбранную модель.

На этом этапе задавайте только общие вопросы по базе знаний и не вводите персональные данные пациента.


## 14. Пациентский помощник

После подключения OpenRouter переключитесь в кабинет пациента и нажмите «Умный помощник». Для проверки обычного RAG задайте вопрос «Что показывает GAD-7?». Для проверки локального ограничения спросите «Можно увеличить дозу лекарства?».

Пациентский корпус является прототипом. Не вводите реальные персональные данные.

Проверка полного демонстрационного сценария: docs/MVP_DEMO_FLOW.md.
